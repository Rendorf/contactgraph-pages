# Graph canvas mouse panning — threat note

Date: 2026-11-21

## Scope and assets

- Adds client-only pointer handling to the existing graph canvas shared by Tags, Organizations, People, and All modes.
- Does not add an endpoint, dependency, permission, persisted value, network request, or contact-data mutation.
- Inputs are browser pointer coordinates, pointer type, button, primary-pointer state, and the current canvas scroll position.

## Abuse and failure cases

- A drag could accidentally activate a person, tag, or organization node.
- Secondary mouse buttons, touch gestures, or interactive controls could be captured unexpectedly.
- Pointer release outside the canvas could leave the interface in a stuck dragging state.
- Repeated pointer events could produce excessive component renders.

## Mitigations and verification

- Panning starts only for the primary left mouse button on non-interactive canvas space.
- A four-pixel threshold separates clicks from intentional drags; a completed drag suppresses the resulting click.
- Pointer capture keeps movement and release paired with the canvas, including cancellation and lost-capture cleanup.
- Touch pointers are excluded, preserving the existing two-finger pinch gesture.
- Scroll positions are updated directly without React renders or persistence.
- Unit tests cover input gating, threshold behavior, both pan axes, initial centering, and shared-hook use by every graph mode. A direction mutation was introduced temporarily and the test failed as expected before the correct implementation was restored.
